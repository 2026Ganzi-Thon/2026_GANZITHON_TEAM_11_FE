# 양 세는 밤

고민을 적고 정한 수만큼 양을 세며 하루를 마무리하는 Android 앱입니다.

2026 간지톤 11팀 프론트엔드 저장소입니다.

## 개발 환경

- Expo SDK 58 · React Native · TypeScript · Expo Router
- Node.js 24.15.0 (`.nvmrc`) · npm 11.12.1
- Android Studio, Android SDK, JDK 21
- Android 에뮬레이터 또는 USB 디버깅이 활성화된 Android 기기

## 실행

```sh
npm ci
npm run android
```

`npm run android`는 `android/`가 없으면 네이티브 프로젝트를 생성하고, 개발용 앱을 빌드·설치한 뒤 Metro를 실행합니다. `android/`가 이미 있으면 자동 prebuild를 건너뜁니다. Android SDK와 JDK가 환경에 설정되어 있어야 합니다. 첫 빌드에는 SDK 구성 요소와 Gradle 의존성 다운로드가 필요할 수 있습니다.

개발용 앱이 설치된 뒤에는 다음 명령으로 Metro를 다시 실행합니다.

```sh
npm start
```

네이티브 의존성, `app.json`의 화면 방향·scheme, config plugin 설정 등을 바꾸면 아래 순서로 Android 프로젝트를 재생성한 뒤 빌드합니다.

```sh
npx expo prebuild --clean --platform android
npm run android
```

`--clean`은 기존 `android/`를 삭제하고 다시 생성하므로 해당 폴더의 수동 변경도 지워집니다. 필요한 변경은 실행 전에 보존하고 `app.json`이나 Expo config plugin에 반영합니다. 생성된 `android/`, `ios/`는 Git에 포함하지 않으며, 네이티브 설정은 `app.json`과 Expo config plugin으로 관리합니다.

## 검사

```sh
npm run check          # 타입, ESLint, Prettier 검사
npm run test:ci        # Jest 실행
npm run bundle:android # Android JavaScript 번들 생성
```

Jest는 API 요청·오류·취소 처리, 입력 검증, 화면 이동과 mock 응답 연동을 검사합니다. 테스트 파일이 없으면 `test:ci`가 실패합니다. 자동 테스트와 번들 검사는 실제 서버 연동, APK 빌드, 기기 검증을 대신하지 않습니다.

PR에서는 위 검사를 GitHub Actions로 실행합니다. 변경한 화면은 Android에서도 확인하고, PR에 검증 결과와 남은 제한 사항을 기록합니다. 코드 포맷은 `npm run format`으로 적용합니다.

## 로그인 화면 미리보기

개발 빌드의 시작 화면에서 **로그인 화면 미리보기**를 눌러 성공 응답·로그인 정보 오류·연결 실패를 선택할 수 있습니다. 가상의 이메일과 비밀번호로 입력 검증, 로딩, 오류 및 재시도를 확인합니다. 실제 서버 호출·인증·토큰 저장은 수행하지 않으며, 비밀번호 찾기는 준비 중 안내만 제공합니다.

`/dev/login`은 개발 빌드에서만 접근할 수 있습니다. 배포 빌드에서는 시작 화면으로 이동하며 미리보기 진입 버튼도 표시하지 않습니다. 로그인 후 실제 화면 분기와 회원가입·비밀번호 재설정은 후속 구현 범위입니다.

로그인 UI는 Figma S-02b를 기준으로 구현했습니다. 배경과 아이콘은 `assets/images/`의 로컬 SVG를 사용하고, Noto Sans KR은 `expo-font` 설정으로 Android 앱에 포함합니다. 이 변경을 처음 적용하거나 폰트·플러그인 설정을 바꾼 경우 위의 네이티브 설정 재생성 절차를 실행해야 합니다.

## API 사용

`.env.example`을 `.env`로 복사하고 `EXPO_PUBLIC_API_BASE_URL`에 `/api/v1`을 포함한 개발 서버 주소를 지정합니다. `EXPO_PUBLIC_*` 값은 앱에 포함되므로 비밀 키를 넣지 않습니다. 현재 초기 화면에서는 API를 호출하지 않습니다.

```ts
import { createApiClient } from './src/api/client';
import { getApiBaseUrl } from './src/api/config';
import type { Bootstrap } from './src/api/contracts';

const api = createApiClient({ baseUrl: getApiBaseUrl() });
// accessToken은 인증 흐름에서 전달받습니다.
const bootstrap = await api.request<Bootstrap>('/bootstrap', { accessToken });
```

요청 경로는 `/bootstrap`처럼 기본 API 경로에 상대적으로 지정합니다. JSON 요청은 `body`, 인증은 `accessToken`, 멱등키는 `idempotencyKey`로 전달합니다. 204 또는 빈 성공 응답은 `undefined`입니다. 응답의 제네릭 타입은 런타임 검증이 아니므로, 화면 연결 시 필수 필드와 허용 상태를 검증해야 합니다.

`ApiError.kind`로 서버 오류(`http`), 연결 실패(`network`), 시간초과(`timeout`), 취소(`aborted`), 잘못된 JSON(`invalid-response`), 잘못된 설정(`configuration`)을 구분합니다. 서버 오류에는 `status`, `code`, `fields`, `requestId`, `retryAfter`가 제공될 수 있습니다. `serverMessage`와 `fields`에는 민감한 내용이 포함될 수 있으므로 오류 객체 전체를 로그에 남기거나 그대로 사용자에게 표시하지 않습니다.

기본 시간제한은 10초이며 `timeoutMs`로 변경할 수 있습니다. 자동 재시도·토큰 갱신·토큰 저장은 아직 포함하지 않습니다. 변경 요청을 재시도할 때는 같은 작업의 멱등키와 본문을 유지하고, 새로운 작업에는 새 키를 전달해야 합니다.

mock은 `createMockFetch`를 클라이언트의 `fetch` 옵션에 직접 주입할 때만 사용합니다. 동일한 클라이언트와 오류 처리를 거치며, 미등록 경로는 501 `MOCK_ROUTE_NOT_FOUND`를 반환하고 실제 네트워크에 연결하지 않습니다. 경로 매칭은 메서드와 전체 pathname 기준이며 query에 따른 응답 분기는 제공하지 않습니다. mock 검증은 실제 인증·서버 구현 검증을 의미하지 않습니다.

```ts
import { createApiClient } from './src/api/client';
import { createMockFetch } from './src/mocks/transport';
import { bootstrapFixture } from './src/mocks/fixtures';

const api = createApiClient({
  baseUrl: 'https://mock.invalid/api/v1',
  fetch: createMockFetch([
    { method: 'GET', path: '/api/v1/bootstrap', body: bootstrapFixture },
  ]),
});
```

## 오늘 밤 화면 미리보기

개발 빌드의 시작 화면에서 **오늘 밤 화면 미리보기**를 열면 고민 입력(N-01) → 양 수 선택(N-02) → 예시 피드(N-03) → 마무리·작성 제안(N-06·07)를 확인할 수 있습니다. Figma의 책장형을 적용하며, 책장형·LP형을 사용자가 선택하는 단계는 포함하지 않습니다.

- 8개 고민 중 하나 선택, 공백 입력 차단, 글자 수 검증. ‘고민 없음’은 입력을 비활성화하고 `worry_text: null`로 전달합니다.
- 기본 15마리, 3~30마리 증감 및 3·10·20·30 프리셋. 양 수 화면에서 돌아오면 입력과 선택값을 유지합니다.
- 성공, 고민 입력 실패 후 재시도, 양 세기 준비 실패 후 재시도를 선택할 수 있습니다. 실패 시 입력을 유지하며, 화면 이탈 시 대기 작업을 취소합니다.
- `/dev/night-entry`는 개발 빌드 전용입니다. 배포 빌드에서는 시작 화면으로 이동합니다. 입력은 메모리에만 두며 미리보기를 닫으면 폐기합니다.

글자 수는 Figma의 **200자**를 임시 적용합니다. API v0.6의 500자 제안과 합의 전이며 `PREVIEW_WORRY_LIMIT`에서 변경할 수 있습니다. 카테고리는 고정 예시이고 서버 `/categories`와 연결하지 않습니다.

이 흐름의 성공은 화면 확인용 예시 응답입니다. 실제 고민 저장·안전 판정·세션 생성은 수행하지 않습니다. 서버 및 Android HTTP 연동, 서버 기준 밤 상태·하루 한 번 기록 규칙·지원 안내 분기는 후속 구현 범위입니다. 실제 연동 시 저장 후 수정 제한과 서버 응답에 따른 화면 분기를 반영해야 합니다.

## 피드 화면 미리보기

개발 빌드의 **피드 화면 미리보기**(`/dev/night-feed`)에서 공감·가벼운 글, 자동 선곡·사용자 추천곡, 뭉치 엽서, 마지막 따뜻한 말 카드를 확인합니다. 불러오기 실패 후 재시도, 긴 글, 볼 수 없는 카드, 빈 피드도 선택할 수 있습니다. 배포 빌드에서는 진입 버튼을 숨기고 직접 접근 시 시작 화면으로 이동합니다.

- 이전·다음 버튼 또는 양 영역의 위·아래 스와이프로 이동합니다. 긴 카드 본문은 별도로 스크롤합니다.
- 이동 중 중복 입력을 막고, 화면 이탈 시 요청·애니메이션을 취소합니다. 기기의 동작 줄이기 설정을 따릅니다.
- 고민 입력에서 진입하면 선택한 3~30마리를 적용합니다. 피드에서 양 수 선택으로 돌아올 때 입력과 선택값을 유지합니다. 진행 위치와 최대로 도달한 위치는 메모리에만 둡니다.
- Figma N-03을 기반으로 로컬 SVG를 사용합니다. 음악 재생은 제외하며 자동 선곡에는 추천 문구·작성자를 표시하지 않습니다. 앨범 이미지가 없거나 로딩에 실패하면 기본 그림을 표시합니다.

카드 배치는 화면 검증용 예시이며 서버의 피드 생성 규칙을 구현하지 않습니다. 종료 화면도 미리보기 종료만 안내합니다. 실제 서버·Android HTTP 연동, 진행 저장·복원·종료, 솜털·털실·곡 담기, 쉼표양과 로그인 연결은 후속 범위입니다. 반응 버튼은 준비 중으로 비활성화합니다.

## 밤 마무리 미리보기

개발 빌드의 **밤 마무리 미리보기**(`/dev/night-closing`)에서 3마리 완료·중도 종료, 종료 응답 유실, 마무리 카드 확인 실패, 작성 선택 실패, 볼 수 없는 마무리 카드, 이미 작성한 밤을 확인합니다. 오늘 밤 입력 흐름에도 동일한 성공 시나리오를 연결합니다. 기존 `/dev/night-feed`는 카드 표시·이동을 독립적으로 확인하는 미리보기로 유지합니다.

- 마지막 카드의 **마무리하기**는 요약으로 이동하며 마지막 따뜻한 카드를 반복하지 않습니다. **그만 세고 싶어요**는 중도 마무리 카드 → 확인 → 요약 → 작성 제안으로 이동합니다.
- 휴대폰 뒤로가기·앱 이탈만으로 종료 요청을 보내지 않습니다. 미리보기를 닫을 때 진행 중인 작업을 취소하고 늦은 응답은 무시합니다. 재실행 시 진행을 복원하지 않습니다.
- 재시도는 동일한 작업 키·입력값을 유지합니다. 마무리 확인이나 작성 선택만 실패했다면 그 단계만 다시 요청합니다. 메모리 mock의 응답 재현이며 실제 서버의 멱등 처리 검증은 아닙니다.
- 볼 수 없는 마무리 카드는 본문과 반응을 숨기고 열람 확인을 보내지 않습니다. 임의의 대체 카드를 생성하지 않습니다.
- **지금 쓸래요**는 작성 화면 준비 중 안내, **아침에 쓸게요**는 휴식 안내로 연결합니다. 실제 카드 작성·예약은 하지 않습니다. 이미 제안이 처리된 예시에서는 중복 제안을 생략합니다.

화면은 Figma N-06·N-07을 기준으로 구현하며 로컬 원본 SVG를 사용합니다. 자동 대기·페이드 시간은 미확정이므로 버튼으로만 전환하고 기기 밝기를 변경하지 않습니다. 실제 `finish`·`closing-view`·`writing-offer` API, 서버 저장권·진행 저장·앱 복원, 04시 마감과 작성 제안 정책의 통합 검증은 후속 범위입니다. 배포 빌드에서는 개발 경로 접근을 차단합니다.

## 아침·양떼 미리보기

개발 빌드의 **아침·양떼 미리보기**(`/dev/morning`)에서 Figma D-01의 양 선택 → D-02의 최소 양떼 홈을 확인합니다. 조회 실패, 데려오기 응답 유실, 양떼 조회 실패, 이미 확정된 선택, 선택 불가 카드, 후보·기록·양떼 없음, 긴 본문 시나리오를 제공합니다. 배포 빌드에서는 접근을 차단합니다.

- 센 양 수·후보 순서·기본 후보·선택 가능 여부는 예시 응답을 사용합니다. 기본 후보는 강조만 하며 자동 저장하지 않습니다. 마무리 카드에는 임의의 순번을 붙이지 않고, 볼 수 없는 카드의 본문은 숨깁니다.
- 데려오기 성공 응답 후에만 반환된 양을 홈에 표시합니다. 요청 중 중복 제출을 막고 실패 시 선택을 유지합니다. 이미 확정되었거나 후보가 변경된 경우 최신 아침 기록을 다시 확인합니다.
- 양떼 조회만 실패하면 성공한 양을 유지하고 목록만 재시도합니다. 목록과 저장 응답에 같은 양이 있으면 ID로 중복 제거합니다. 신규 양을 강조하며 빈 양떼도 안내합니다.
- 양의 색은 카드 종류가 아닌 카테고리·`color_key`를 사용합니다. 기존 카테고리 중 원본 에셋과 대응되는 색만 표시하고 나머지는 중립색으로 표시합니다. 실제 카테고리 색 매핑은 서버·디자인 확정 후 연결합니다.

메모리 mock이며 시나리오를 나갔다 들어오면 초기화됩니다. 밤 미리보기의 기록과 연결되지 않습니다. 실제 서버·Android HTTP 연동, 로그인·저장·복원, 목록 페이지네이션, 자동 데려오기·건너뛰기 정책, 꾸미기·운세·음악 재생은 후속 범위입니다. 홈의 전체 누적 통계는 아직 표시하지 않습니다. 의존성 보안 경고는 [#3](https://github.com/2026Ganzi-Thon/2026_GANZITHON_TEAM_11_FE/issues/3)에서 추적합니다.

## 양 상세 미리보기

개발 빌드의 **양 상세 미리보기**(`/dev/sheep-detail`)에서 양떼의 양을 눌러 D-04 카드·지난 고민·기존 돌아보기를 읽습니다. **아침·양떼 미리보기**에서도 데려온 양과 이전 양을 눌러 상세를 열 수 있습니다. 배포 빌드에서는 개발 경로를 차단합니다.

- 선택한 양 ID로 조회하고 날짜·글 또는 곡·남아 있는 고민·기존 회고를 표시합니다. 마무리 카드나 수치가 없는 기록에는 순번을 만들지 않습니다. 날짜는 채택 시각이 아닌 밤 날짜입니다.
- 삭제된 카드의 본문·곡·작성자는 숨기고 양과 남아 있는 밤 기록은 유지합니다. 고민 없음 또는 고민 원문이 없는 경우 고민·회고를 노출하지 않습니다.
- 조회 실패는 같은 양으로 재시도하고, 403·404는 조회 불가 안내를 표시합니다. 다른 양의 응답이나 화면을 닫은 뒤 도착한 응답은 표시하지 않습니다.
- 상세는 별도 모달로 열립니다. 상단 뒤로가기와 Android 뒤로가기로 닫으면 기존 양떼·스크롤 위치·신규 강조를 유지합니다. 재진입 시 상세는 다시 조회합니다.

메모리 mock만 사용하며 실제 서버·Android HTTP 연동과 소유권 검증은 미완료입니다. 삭제·회고 작성·꾸미기·음악 재생은 제공하지 않고 **카드 쓰기**는 준비 중으로 비활성화합니다. 긴 글·삭제된 카드/고민·고민 없는 밤·기존 회고·조회 실패·없는 양의 예시를 선택할 수 있습니다. 추가 의존성은 없습니다.

### 아침 돌아보기 미리보기

`/dev/morning-reflection`에서 **어젯밤 돌아보기**를 열어 회고 6종을 선택하고 저장할 수 있습니다. 저장된 답변은 같은 밤의 양 상세에 반영됩니다. 조회·저장 재시도, 고민 없음·삭제, 기존 답변, 긴 고민, 저장 불가 시나리오를 제공합니다. 미리보기 안에서만 메모리로 유지되며 나갔다 들어오면 초기화됩니다. 실제 서버·Android HTTP·로그인·영속 저장은 연결되지 않았습니다. 담은 노래·운세·삭제 기능은 포함하지 않습니다.

### 밤→아침 연결 시연

`/dev/night-morning`에서 고민 입력 → 양 수 선택 → 피드 → 마무리 → 다음 아침 이동 → 양 채택 → 회고 → 양 상세를 이어서 확인할 수 있습니다. 기본 양 수는 3이며 3~30으로 바꿀 수 있습니다. 뒤로가기로 피드·마무리를 잠깐 멈추고 같은 위치에서 이어 볼 수 있습니다. 종료·채택 응답 유실 시나리오는 재시도해도 같은 밤과 양을 유지합니다.

하나의 예시 밤(2026-11-12)을 메모리로 연결하며, 시연 종료·앱 재실행 시 초기화됩니다. 실제 서버·Android HTTP·로그인·영속 저장·안전 검사·시간 판정·추천/피드 배치 규칙은 검증하지 않습니다. **다음 아침으로 이동**은 개발 경로에만 있으며 배포 빌드에서는 이 경로 접근을 차단합니다. 기존 개별 미리보기도 유지합니다.

### 노래 담기와 아침 목록

`/dev/saved-songs`의 **밤부터 노래 담기 시연**은 6마리로 시작합니다. 3·4번째 노래 카드에서 담기·해제한 기록을 아침의 **담은 노래 보기**에서 확인하고 취소할 수 있습니다. 같은 카드의 담기는 중복되지 않으며 아침에는 새로 담을 수 없습니다. 목록에는 Spotify 검색 연결과 `제목 · 가수` 복사를 제공합니다. 검색은 곡 정보로 만든 Spotify HTTPS 주소를 사용하며, 앱 내부 재생이나 음악 검색 API는 포함하지 않습니다.

**느린 노래 담기 시연**은 변경 응답을 5초 지연합니다. 담기·담기 취소 중에는 이전/다음 양과 양 이동 동작을 잠시 막고 완료·실패 후 다시 허용합니다. 이동 애니메이션 중에는 노래 변경을 시작하지 않습니다. 피드를 나가거나 그만 세면 진행 중인 요청을 취소하며, 변경 중 안내에 이 차이를 표시합니다.

목록 예시는 빈 상태·조회/취소 실패·긴 곡 정보·외부 연결/복사 실패 시나리오를 제공합니다. 예시 기록은 메모리에만 유지되고 미리보기를 나가면 초기화됩니다. 실제 서버·Android HTTP·로그인·영속 저장은 미연결입니다. `expo-clipboard`가 추가됐으므로 기존 개발 앱도 `npm run android`로 다시 빌드·설치해야 합니다. Metro 새로고침만으로 네이티브 모듈이 추가되지는 않습니다.

Spotify가 일반 검색 화면으로 이동하면 복사한 곡 정보를 검색창에 붙여넣어 사용할 수 있습니다.

### 내 카드 목록·검수 상태

개발 빌드에서 `yangsebam://dev/my-cards`를 열면 짧은 글·노래 추천의 종류, 작성일, 받은 털실 수와 검수 상태를 확인할 수 있습니다. 전체·검수 중·반려 필터와 반려 사유를 제공하며, 목록은 추가 불러오기로 이어집니다. 다른 화면의 개발 미리보기 진입점은 유지합니다.

- 첫 조회 실패는 처음부터 다시 불러옵니다. 추가 조회 실패는 확인한 목록을 유지한 채 같은 페이지를 재시도합니다. 중복 카드 ID를 합치고, 필터 전환·나가기 이후의 늦은 응답은 표시하지 않습니다.
- 빈 목록·첫/추가 조회 실패·느린 조회·긴 글/곡 정보/반려 사유 예시를 제공합니다. 글자 확대 시 카드 높이와 필터가 늘어나며 내용을 스크롤할 수 있습니다.
- 각 카드의 삭제를 누르면 C-05a 확인창을 엽니다. 취소는 요청하지 않고, 지우기가 확인된 뒤 목록에서 제거합니다. 처리 중 중복 확인·창 닫기를 막으며, 실패하면 같은 카드로 재시도합니다. 응답 유실 뒤에도 반복 삭제를 확인할 수 있습니다.
- 삭제 후 이전 페이지 요청을 취소하고 첫 페이지부터 다시 확인합니다. 삭제한 ID는 같은 조회 소스 안에서 숨기고, 필터·늦은 응답으로 다시 나타나지 않게 합니다. 재조회 실패 시 남은 카드를 유지하고 조회만 재시도합니다. 삭제 실패·느린 삭제·응답 유실·삭제 후 조회 실패·마지막 카드 예시를 제공합니다.
- 내 카드에서 시작한 새 글·노래 작성과 목록·삭제는 같은 시연의 메모리 예시로 연결합니다. 다시 시작하면 초기화되며 실제 서버·Android HTTP·로그인·영속 저장·운영 검수·실제 피드/털실/양떼 반영과 연결하지 않았습니다. 확인창은 이 목록의 카드와 털실 기록을 대상으로 합니다. 반려 수정/재제출 연결은 후속 범위입니다. 새 카드 작성은 아래 연결 흐름을 참고하세요. 개발 경로는 배포 빌드에서 차단합니다.

### 털실 보내기·취소

개발 빌드의 **털실 반응 미리보기**(`/dev/yarn`)와 밤→아침 연결 시연에서 피드 카드에 털실을 보내거나 취소할 수 있습니다. 글·노래·시드·뭉치·AI 선곡 카드에 반응할 수 있습니다. 솜털 표시·해제는 아래 솜털 미리보기와 연결 시연에서 확인합니다. 기존 개별 화면 미리보기는 반응 어댑터를 연결하지 않으면 준비 안내를 표시합니다.

- 응답을 확인한 상태만 보낸 아이콘으로 표시합니다. 처리 중에는 마지막 선택과 대기 상태를 구분하며, 빠른 보내기·취소는 카드별로 순서대로 처리해 최종 선택에 맞춥니다.
- 다른 양으로 이동해도 요청을 유지하고, 돌아오면 해당 카드의 상태·실패 안내를 확인할 수 있습니다. 피드를 나가거나 마치면 남은 요청을 취소합니다. 연결 시연을 잠시 멈췄다 이어 보면 확정된 상태는 유지됩니다. 기존 노래 담기 중 이동 제한은 그대로 적용합니다.
- 실패하면 확인된 마지막 상태와 다시 시도를 표시합니다. 응답 유실 뒤에도 마지막 목표 상태를 다시 요청합니다. `CARD_UNAVAILABLE`·404·410 응답에서는 카드 본문과 반응을 숨기며, 프로필·동의 관련 403은 삭제로 처리하지 않습니다.
- Figma N-03a·1/2/3의 원본 기본/보냄 아이콘과 확인 토스트를 사용합니다. 토스트는 5초간 표시하고 확정된 버튼 상태는 남깁니다. 글자 확대에서는 반응 영역을 늘리고 안내 문장을 줄바꿈합니다. 새 이동 애니메이션은 추가하지 않습니다.

성공·5초 지연·보내기/취소 실패·응답 유실·오프라인·삭제·긴 글 예시를 제공합니다. 오류·오프라인은 고정 시나리오이며 실제 연결 상태를 감지하지 않습니다. 기록은 시연 안의 메모리에만 있고 시연 종료·앱 재실행 시 초기화됩니다. 실제 서버·Android HTTP·로그인·영속 저장·작성자 전달·알림·받은 털실 집계·인기 순위는 미연결/미검증입니다. 실제 요청의 취소·응답 유실 뒤 서버 상태 복구는 연동 시 검증해야 합니다. 마무리 카드·양 상세에서 새로 반응하는 동작은 이번 범위에 포함하지 않습니다. 배포 빌드의 개발 경로 접근은 차단하며 새 네이티브 의존성은 없습니다.

### 솜털과 아침 후보

개발 빌드의 **솜털과 아침 후보 미리보기**(`/dev/fluff`)에서 본 카드에 솜털을 붙이거나 뗄 수 있습니다. **밤부터 아침 후보 시연**은 6마리로 시작하며 밤 마무리의 솜털 개수와 다음 아침의 후보 순서를 연결합니다. 솜털은 아침 데려오기 후보에 표시하는 기능이며 별도 보관함은 제공하지 않습니다.

- 응답으로 확인한 선택과 처리 중 목표를 구분합니다. 빠른 연속 조작은 카드별로 순서대로 처리하고, 다른 양으로 이동해도 요청과 상태를 유지합니다. 실패 시 마지막 확인 상태와 재시도를 표시하며 응답 유실 뒤에도 최종 목표 상태를 다시 요청합니다.
- 솜털 확인 중에는 상단에 대기 안내를 표시하고 일반·중도 밤 마무리를 막습니다. 다른 양은 계속 볼 수 있고, 뒤로 나가거나 개별 미리보기를 종료하면 남은 요청을 취소합니다. 연결 시연을 이어 보면 저장된 표시가 유지됩니다. 노래 담기의 이동 제한과 털실 상태는 독립적으로 유지합니다.
- 밤 마감 응답은 모든 솜털 조작을 읽기 전용으로 바꾸고, 삭제된 카드 응답은 본문·반응을 숨깁니다. 확인한 밤 기록의 유효한 카드 ID를 중복 제거해 솜털 개수를 표시합니다.
- 아침 후보는 솜털 우선 → 최근 본 순 → 카드 ID 순으로 제공하고, 각 표시된 후보에 ‘솜털’을 붙입니다. 기본 선택은 정렬과 별개로 마지막 유효한 따뜻한 카드이며, 없으면 마지막 유효한 일반 카드입니다. 최대 도달 범위와 실제 표시한 마무리 카드만 후보로 제공합니다. 화면은 어댑터가 반환한 순서와 기본 선택을 따릅니다.
- Figma 원본 솜털 아이콘·확인 토스트를 사용하고, 글자 확대에서도 라벨·안내를 줄바꿈합니다. 선택 여부는 라벨과 접근성 선택 상태로 구분합니다. 다른 카드의 결과나 다른 반응 토스트를 겹쳐 표시하지 않습니다.

성공·5초 지연·붙이기/떼기 실패·응답 유실·오프라인·삭제·밤 마감·긴 글 예시를 제공합니다. 오류·마감·오프라인은 고정 시나리오이며, 아침 이동은 개발용 수동 전환입니다. 실제 04시 판정·서버 진행 저장 순서·Android HTTP·로그인·영속 저장·오프라인 복구는 미연결/미검증입니다. 상태는 같은 시연의 메모리 안에만 유지하고 종료·앱 재실행 시 초기화합니다. 마무리 카드·양 상세에서 새로 솜털을 붙이는 동작은 포함하지 않습니다. 새 네이티브 의존성은 없으며 배포 빌드의 개발 경로 접근을 차단합니다.

### 짧은 글 카드 쓰기

개발 빌드의 **글 카드 쓰기 미리보기**(`/dev/text-card`)에서 Figma C-01·C-02·C-04를 기준으로 고민 분류 7종 → 짧은 글 → 검수 대기 접수를 확인합니다. **밤부터 글 카드 쓰기 시연** 또는 `/dev/night-morning`의 **지금 쓸래요**에서도 이어집니다. 작성창을 닫아도 같은 시연 안에서는 초안을 이어 쓸 수 있고, **아침에 쓸게요**로 미룰 수 있습니다. 접수가 확인되면 **이제 잘게요**로 밤을 마칩니다. 배포 빌드에서는 개발 경로 접근을 차단합니다.

글자 수는 Figma의 200자를 임시 적용하며 API의 300자 제안과 합의 전입니다. 앞뒤 공백을 제외한 유니코드 코드 포인트를 세고, 초과 입력을 임의로 자르지 않습니다. 중복 제출을 막고 같은 글의 재시도 키를 유지합니다. 입력 오류·응답 유실·도움 안내·검수 요청 불가·작성 진입 만료 시나리오를 제공합니다. 오류·도움 안내는 글 내용과 무관한 고정 예시입니다.

초안과 접수 결과는 메모리에서만 유지됩니다. 시연 종료·앱 재실행 시 초기화되며 실제 서버·Android HTTP·로그인·계정별 영속 저장·안전 검사·운영 검수와 연결되지 않습니다. 접수는 승인 완료를 뜻하지 않으며 검수 대기 카드는 아침 후보에 추가하지 않습니다. 도움 안내는 초안 복귀까지만 제공하고 실제 지원 자원 연결, 밤·아침 작성 기록과 내 카드 목록의 통합·재제출은 후속 범위입니다. 아침 배너 작성은 아래 연결 시연에서 확인합니다. 새 네이티브 의존성은 없습니다.

### 노래 카드 추천 작성

개발 빌드의 **노래 카드 추천 미리보기**(`/dev/song-card`)에서 C-01의 고민 분류 7종·카드 종류 선택 → C-03의 곡 선택·추천 한 줄 → C-04의 검수 대기 접수를 확인합니다. 밤→아침 연결 시연의 **지금 쓸래요**에서도 글·노래를 선택합니다. 종류별 초안과 마지막 작성 종류는 같은 시연 안에서 유지되며, 뒤로 나갔다 **카드 이어 쓰기**로 복원할 수 있습니다. 기존 글 전용 미리보기도 유지합니다.

- 검색어는 앞뒤 공백 제외 Unicode 1~100자이며 초과 입력은 안내하고 검색하지 않습니다. 검색은 입력 중지 300ms 뒤 고정 예시 목록을 반환합니다. 실제 검색어 일치나 외부 검색 품질을 검증하지 않습니다. 검색어 변경·직접 입력 전환·화면 종료 뒤 오래된 응답은 표시하지 않습니다. 검색 장애는 재시도, 빈 결과는 제목·가수 직접 입력으로 구분합니다.
- 글자 확대 시 곡명·가수를 줄바꿈하고 곡 정보 행을 단색으로 표시해 배경 장식과 분리합니다.
- 검색 선택은 `track_id`, 직접 입력은 `manual_track`만 전송하는 mock 계약입니다. 제목·가수는 각각 앞뒤 공백 제외 Unicode 1~200자, 추천 문장은 Figma의 1~50자를 임시 적용합니다(API의 150자 제안과 합의 필요). 가사·음원 재생을 제공하지 않습니다.
- 접수 중 입력·중복 제출·일반 뒤로가기를 막고 결과 화면을 표시합니다. 오류 후 초안을 유지하며, 같은 본문의 재시도는 같은 키를 씁니다. 접수 확정 후 새 수정본은 밤 작성 상태를 확인하도록 안내합니다. 소스 교체·시연 종료는 진행 중 작업을 취소하고 늦은 응답을 무시합니다.
- 검색 실패·빈 결과·느린 검색·긴 곡명·접수 실패·응답 유실·느린 접수·입력 오류·검수 불가·도움 안내·작성 진입 만료 예시를 제공합니다. 오류와 도움 안내는 고정 예시이며 추천 문장을 분석하지 않습니다.
- 실제 서버·음악 검색 API·Android HTTP·인증·영속 저장·안전 검사·운영 검수와 연결하지 않았습니다. 접수 대기 카드는 아침 후보에 넣지 않습니다. 밤·아침 작성 기록의 내 카드 목록 통합과 노래 카드 재제출은 후속 범위입니다. 개발 경로는 배포 빌드에서 차단하며 새 네이티브 의존성은 없습니다.

### 아침에 미뤄 둔 카드 쓰기

`/dev/night-morning`에서 **아침에 쓸게요** → 다음 아침 → 양 데려오기 → **미뤄 둔 카드 쓰기**로 글·노래 작성을 이어 갑니다. 배너는 해당 밤의 작성 제안이 미뤄진 경우에만 홈에 나타납니다. 작성을 닫으면 같은 시연의 초안·곡·선택을 유지하고, 접수 확인 후 **아침 홈으로** 돌아갑니다. 밤에 시작한 작성은 기존 **이제 잘게요** 경로를 유지합니다.

- 접수 확인 후 해당 밤 ID로 아침 상태를 다시 조회합니다. 조회가 실패해도 재작성을 열지 않고 **작성 상태 다시 확인**으로 조회만 재시도합니다.
- 접수 실패·응답 유실·접수 후 상태 조회 실패 시나리오를 제공합니다. 응답이 유실돼도 같은 본문과 키로 재시도하며, 글·노래를 합쳐 해당 밤의 제안 한 번만 접수합니다. 검수 대기 카드는 아침 후보에 추가하지 않습니다.
- 밤에 응답하지 않았거나 쓰다 만 제안도 개발용 아침 전환 때 미룬 상태로 이어집니다. 실제 04시 판정·서버·Android HTTP·로그인·영속 저장·실제 곡 검색 API는 연결하지 않았습니다. 시연 종료·앱 재실행 시 초기화되며 배포 빌드에서는 개발 경로 접근을 차단합니다. 새 네이티브 의존성은 없습니다.

### 내 카드에서 새 카드 작성

`/dev/my-cards`에서 **+ 카드 쓰기** → 고민 분류·글/노래 선택 → 작성 → 접수 → **내 카드로**를 확인합니다. 내 카드에서 시작하는 낮 작성은 밤 ID를 보내지 않습니다. 접수 후 전체 탭·첫 페이지·목록 상단으로 돌아가 새 카드를 `검수 중`으로 확인하며, 검수 중 필터와 삭제에도 같은 기록을 사용합니다.

- 취소하면 같은 시연의 글·곡·추천 문장과 재시도 키를 유지합니다. 접수가 확인된 작성은 종료하고 다음 카드는 빈 초안과 새 키·ID로 시작합니다.
- 응답 유실 시 최초 요청의 본문·키를 편집 초안과 별도로 보존합니다. 본문·추천 문장·곡을 바꾸거나 원문으로 되돌린 뒤 닫았다 열어도 **이전 접수 확인**으로 최초 요청의 접수를 복구합니다. 수정본의 새 제출은 최초 접수가 확인될 때까지 막으며, 원문과 다른 새 키로 복구하지 않습니다. 글·노래 종류를 바꿔 중복 접수할 수 없습니다. 접수 후 목록 조회 실패는 접수 확인 안내를 유지하고 조회만 재시도합니다. 소스 교체·시연 종료 시 진행 중 요청은 취소하고 늦은 응답은 무시합니다.
- 빈 목록 첫 작성, 접수 실패·응답 유실·느린 접수·접수 후 목록 조회 실패·곡 직접 입력 시나리오를 제공합니다. 글 200자·추천 문장 50자 임시 기준은 기존 미리보기와 같습니다.
- 작성·조회·삭제·곡 검색은 메모리 mock입니다. 실제 서버·Android HTTP·로그인·계정별 영속 저장·낮/밤 시간 판정·곡 검색 API·안전 검사·운영 검수는 연결하지 않았습니다. 밤·아침 시연에서 접수한 카드는 별도 기록이며 이번 목록에 통합하지 않습니다. 시연 종료·앱 재실행 시 초기화됩니다. 개발 경로의 배포 차단을 유지하며 새 네이티브 의존성은 없습니다.
