# 양 세는 밤

고민을 적고 정한 수만큼 양을 세며 하루를 마무리하는 Android 앱입니다.

2026 간지톤 11팀 프론트엔드 저장소입니다.

## 개발 환경

- Expo SDK 58 · React Native · TypeScript · Expo Router
- Node.js 24.15.0 (`.nvmrc`) · npm 11.12.1
- Android Studio, Android SDK, JDK 21
- Android 에뮬레이터 또는 USB 디버깅이 활성화된 Android 기기

## 실행

```sh
npm ci
npm run android
```

`npm run android`는 `android/`가 없으면 네이티브 프로젝트를 생성하고, 개발용 앱을 빌드·설치한 뒤 Metro를 실행합니다. `android/`가 이미 있으면 자동 prebuild를 건너뜁니다. Android SDK와 JDK가 환경에 설정되어 있어야 합니다. 첫 빌드에는 SDK 구성 요소와 Gradle 의존성 다운로드가 필요할 수 있습니다.

개발용 앱이 설치된 뒤에는 다음 명령으로 Metro를 다시 실행합니다.

```sh
npm start
```

네이티브 의존성, `app.json`의 화면 방향·scheme, config plugin 설정 등을 바꾸면 아래 순서로 Android 프로젝트를 재생성한 뒤 빌드합니다.

```sh
npx expo prebuild --clean --platform android
npm run android
```

`--clean`은 기존 `android/`를 삭제하고 다시 생성하므로 해당 폴더의 수동 변경도 지워집니다. 필요한 변경은 실행 전에 보존하고 `app.json`이나 Expo config plugin에 반영합니다. 생성된 `android/`, `ios/`는 Git에 포함하지 않으며, 네이티브 설정은 `app.json`과 Expo config plugin으로 관리합니다.

## 검사

```sh
npm run check          # 타입, ESLint, Prettier 검사
npm run test:ci        # Jest 실행
npm run bundle:android # Android JavaScript 번들 생성
```

Jest는 API 요청·오류·취소 처리, 입력 검증, 화면 이동과 mock 응답 연동을 검사합니다. 테스트 파일이 없으면 `test:ci`가 실패합니다. 자동 테스트와 번들 검사는 실제 서버 연동, APK 빌드, 기기 검증을 대신하지 않습니다.

PR에서는 위 검사를 GitHub Actions로 실행합니다. 변경한 화면은 Android에서도 확인하고, PR에 검증 결과와 남은 제한 사항을 기록합니다. 코드 포맷은 `npm run format`으로 적용합니다.

## 로그인 화면 미리보기

개발 빌드의 시작 화면에서 **로그인 화면 미리보기**를 눌러 성공 응답·로그인 정보 오류·연결 실패를 선택할 수 있습니다. 가상의 이메일과 비밀번호로 입력 검증, 로딩, 오류 및 재시도를 확인합니다. 실제 서버 호출·인증·토큰 저장은 수행하지 않으며, 비밀번호 찾기는 준비 중 안내만 제공합니다.

`/dev/login`은 개발 빌드에서만 접근할 수 있습니다. 배포 빌드에서는 시작 화면으로 이동하며 미리보기 진입 버튼도 표시하지 않습니다. 로그인 후 실제 화면 분기와 회원가입·비밀번호 재설정은 후속 구현 범위입니다.

로그인 UI는 Figma S-02b를 기준으로 구현했습니다. 배경과 아이콘은 `assets/images/`의 로컬 SVG를 사용하고, Noto Sans KR은 `expo-font` 설정으로 Android 앱에 포함합니다. 이 변경을 처음 적용하거나 폰트·플러그인 설정을 바꾼 경우 위의 네이티브 설정 재생성 절차를 실행해야 합니다.

## API 사용

`.env.example`을 `.env`로 복사하고 `EXPO_PUBLIC_API_BASE_URL`에 `/api/v1`을 포함한 개발 서버 주소를 지정합니다. `EXPO_PUBLIC_*` 값은 앱에 포함되므로 비밀 키를 넣지 않습니다. 현재 초기 화면에서는 API를 호출하지 않습니다.

```ts
import { createApiClient } from './src/api/client';
import { getApiBaseUrl } from './src/api/config';
import type { Bootstrap } from './src/api/contracts';

const api = createApiClient({ baseUrl: getApiBaseUrl() });
// accessToken은 인증 흐름에서 전달받습니다.
const bootstrap = await api.request<Bootstrap>('/bootstrap', { accessToken });
```

요청 경로는 `/bootstrap`처럼 기본 API 경로에 상대적으로 지정합니다. JSON 요청은 `body`, 인증은 `accessToken`, 멱등키는 `idempotencyKey`로 전달합니다. 204 또는 빈 성공 응답은 `undefined`입니다. 응답의 제네릭 타입은 런타임 검증이 아니므로, 화면 연결 시 필수 필드와 허용 상태를 검증해야 합니다.

`ApiError.kind`로 서버 오류(`http`), 연결 실패(`network`), 시간초과(`timeout`), 취소(`aborted`), 잘못된 JSON(`invalid-response`), 잘못된 설정(`configuration`)을 구분합니다. 서버 오류에는 `status`, `code`, `fields`, `requestId`, `retryAfter`가 제공될 수 있습니다. `serverMessage`와 `fields`에는 민감한 내용이 포함될 수 있으므로 오류 객체 전체를 로그에 남기거나 그대로 사용자에게 표시하지 않습니다.

기본 시간제한은 10초이며 `timeoutMs`로 변경할 수 있습니다. 자동 재시도·토큰 갱신·토큰 저장은 아직 포함하지 않습니다. 변경 요청을 재시도할 때는 같은 작업의 멱등키와 본문을 유지하고, 새로운 작업에는 새 키를 전달해야 합니다.

mock은 `createMockFetch`를 클라이언트의 `fetch` 옵션에 직접 주입할 때만 사용합니다. 동일한 클라이언트와 오류 처리를 거치며, 미등록 경로는 501 `MOCK_ROUTE_NOT_FOUND`를 반환하고 실제 네트워크에 연결하지 않습니다. 경로 매칭은 메서드와 전체 pathname 기준이며 query에 따른 응답 분기는 제공하지 않습니다. mock 검증은 실제 인증·서버 구현 검증을 의미하지 않습니다.

```ts
import { createApiClient } from './src/api/client';
import { createMockFetch } from './src/mocks/transport';
import { bootstrapFixture } from './src/mocks/fixtures';

const api = createApiClient({
  baseUrl: 'https://mock.invalid/api/v1',
  fetch: createMockFetch([
    { method: 'GET', path: '/api/v1/bootstrap', body: bootstrapFixture },
  ]),
});
```

## 오늘 밤 화면 미리보기

개발 빌드의 시작 화면에서 **오늘 밤 화면 미리보기**를 열면 고민 입력(N-01) → 양 수 선택(N-02) → 예시 피드(N-03) → 마무리·작성 제안(N-06·07)를 확인할 수 있습니다. Figma의 책장형을 적용하며, 책장형·LP형을 사용자가 선택하는 단계는 포함하지 않습니다.

- 8개 고민 중 하나 선택, 공백 입력 차단, 글자 수 검증. ‘고민 없음’은 입력을 비활성화하고 `worry_text: null`로 전달합니다.
- 기본 15마리, 3~30마리 증감 및 3·10·20·30 프리셋. 양 수 화면에서 돌아오면 입력과 선택값을 유지합니다.
- 성공, 고민 입력 실패 후 재시도, 양 세기 준비 실패 후 재시도를 선택할 수 있습니다. 실패 시 입력을 유지하며, 화면 이탈 시 대기 작업을 취소합니다.
- `/dev/night-entry`는 개발 빌드 전용입니다. 배포 빌드에서는 시작 화면으로 이동합니다. 입력은 메모리에만 두며 미리보기를 닫으면 폐기합니다.

글자 수는 Figma의 **200자**를 임시 적용합니다. API v0.6의 500자 제안과 합의 전이며 `PREVIEW_WORRY_LIMIT`에서 변경할 수 있습니다. 카테고리는 고정 예시이고 서버 `/categories`와 연결하지 않습니다.

이 흐름의 성공은 화면 확인용 예시 응답입니다. 실제 고민 저장·안전 판정·세션 생성은 수행하지 않습니다. 서버 및 Android HTTP 연동, 서버 기준 밤 상태·하루 한 번 기록 규칙·지원 안내 분기는 후속 구현 범위입니다. 실제 연동 시 저장 후 수정 제한과 서버 응답에 따른 화면 분기를 반영해야 합니다.

## 피드 화면 미리보기

개발 빌드의 **피드 화면 미리보기**(`/dev/night-feed`)에서 공감·가벼운 글, 자동 선곡·사용자 추천곡, 뭉치 엽서, 마지막 따뜻한 말 카드를 확인합니다. 불러오기 실패 후 재시도, 긴 글, 볼 수 없는 카드, 빈 피드도 선택할 수 있습니다. 배포 빌드에서는 진입 버튼을 숨기고 직접 접근 시 시작 화면으로 이동합니다.

- 이전·다음 버튼 또는 양 영역의 위·아래 스와이프로 이동합니다. 긴 카드 본문은 별도로 스크롤합니다.
- 이동 중 중복 입력을 막고, 화면 이탈 시 요청·애니메이션을 취소합니다. 기기의 동작 줄이기 설정을 따릅니다.
- 고민 입력에서 진입하면 선택한 3~30마리를 적용합니다. 피드에서 양 수 선택으로 돌아올 때 입력과 선택값을 유지합니다. 진행 위치와 최대로 도달한 위치는 메모리에만 둡니다.
- Figma N-03을 기반으로 로컬 SVG를 사용합니다. 음악 재생은 제외하며 자동 선곡에는 추천 문구·작성자를 표시하지 않습니다. 앨범 이미지가 없거나 로딩에 실패하면 기본 그림을 표시합니다.

카드 배치는 화면 검증용 예시이며 서버의 피드 생성 규칙을 구현하지 않습니다. 종료 화면도 미리보기 종료만 안내합니다. 실제 서버·Android HTTP 연동, 진행 저장·복원·종료, 솜털·털실·곡 담기, 쉼표양과 로그인 연결은 후속 범위입니다. 반응 버튼은 준비 중으로 비활성화합니다.

## 밤 마무리 미리보기

개발 빌드의 **밤 마무리 미리보기**(`/dev/night-closing`)에서 3마리 완료·중도 종료, 종료 응답 유실, 마무리 카드 확인 실패, 작성 선택 실패, 볼 수 없는 마무리 카드, 이미 작성한 밤을 확인합니다. 오늘 밤 입력 흐름에도 동일한 성공 시나리오를 연결합니다. 기존 `/dev/night-feed`는 카드 표시·이동을 독립적으로 확인하는 미리보기로 유지합니다.

- 마지막 카드의 **마무리하기**는 요약으로 이동하며 마지막 따뜻한 카드를 반복하지 않습니다. **그만 세고 싶어요**는 중도 마무리 카드 → 확인 → 요약 → 작성 제안으로 이동합니다.
- 휴대폰 뒤로가기·앱 이탈만으로 종료 요청을 보내지 않습니다. 미리보기를 닫을 때 진행 중인 작업을 취소하고 늦은 응답은 무시합니다. 재실행 시 진행을 복원하지 않습니다.
- 재시도는 동일한 작업 키·입력값을 유지합니다. 마무리 확인이나 작성 선택만 실패했다면 그 단계만 다시 요청합니다. 메모리 mock의 응답 재현이며 실제 서버의 멱등 처리 검증은 아닙니다.
- 볼 수 없는 마무리 카드는 본문과 반응을 숨기고 열람 확인을 보내지 않습니다. 임의의 대체 카드를 생성하지 않습니다.
- **지금 쓸래요**는 작성 화면 준비 중 안내, **아침에 쓸게요**는 휴식 안내로 연결합니다. 실제 카드 작성·예약은 하지 않습니다. 이미 제안이 처리된 예시에서는 중복 제안을 생략합니다.

화면은 Figma N-06·N-07을 기준으로 구현하며 로컬 원본 SVG를 사용합니다. 자동 대기·페이드 시간은 미확정이므로 버튼으로만 전환하고 기기 밝기를 변경하지 않습니다. 실제 `finish`·`closing-view`·`writing-offer` API, 서버 저장권·진행 저장·앱 복원, 04시 마감과 작성 제안 정책의 통합 검증은 후속 범위입니다. 배포 빌드에서는 개발 경로 접근을 차단합니다.

## 아침·양떼 미리보기

개발 빌드의 **아침·양떼 미리보기**(`/dev/morning`)에서 Figma D-01의 양 선택 → D-02의 최소 양떼 홈을 확인합니다. 조회 실패, 데려오기 응답 유실, 양떼 조회 실패, 이미 확정된 선택, 선택 불가 카드, 후보·기록·양떼 없음, 긴 본문 시나리오를 제공합니다. 배포 빌드에서는 접근을 차단합니다.

- 센 양 수·후보 순서·기본 후보·선택 가능 여부는 예시 응답을 사용합니다. 기본 후보는 강조만 하며 자동 저장하지 않습니다. 마무리 카드에는 임의의 순번을 붙이지 않고, 볼 수 없는 카드의 본문은 숨깁니다.
- 데려오기 성공 응답 후에만 반환된 양을 홈에 표시합니다. 요청 중 중복 제출을 막고 실패 시 선택을 유지합니다. 이미 확정되었거나 후보가 변경된 경우 최신 아침 기록을 다시 확인합니다.
- 양떼 조회만 실패하면 성공한 양을 유지하고 목록만 재시도합니다. 목록과 저장 응답에 같은 양이 있으면 ID로 중복 제거합니다. 신규 양을 강조하며 빈 양떼도 안내합니다.
- 양의 색은 카드 종류가 아닌 카테고리·`color_key`를 사용합니다. 기존 카테고리 중 원본 에셋과 대응되는 색만 표시하고 나머지는 중립색으로 표시합니다. 실제 카테고리 색 매핑은 서버·디자인 확정 후 연결합니다.

메모리 mock이며 시나리오를 나갔다 들어오면 초기화됩니다. 밤 미리보기의 기록과 연결되지 않습니다. 실제 서버·Android HTTP 연동, 로그인·저장·복원, 목록 페이지네이션, 자동 데려오기·건너뛰기 정책, 꾸미기·운세·음악 재생은 후속 범위입니다. 홈의 전체 누적 통계는 아직 표시하지 않습니다. 의존성 보안 경고는 [#3](https://github.com/2026Ganzi-Thon/2026_GANZITHON_TEAM_11_FE/issues/3)에서 추적합니다.

## 양 상세 미리보기

개발 빌드의 **양 상세 미리보기**(`/dev/sheep-detail`)에서 양떼의 양을 눌러 D-04 카드·지난 고민·기존 돌아보기를 읽습니다. **아침·양떼 미리보기**에서도 데려온 양과 이전 양을 눌러 상세를 열 수 있습니다. 배포 빌드에서는 개발 경로를 차단합니다.

- 선택한 양 ID로 조회하고 날짜·글 또는 곡·남아 있는 고민·기존 회고를 표시합니다. 마무리 카드나 수치가 없는 기록에는 순번을 만들지 않습니다. 날짜는 채택 시각이 아닌 밤 날짜입니다.
- 삭제된 카드의 본문·곡·작성자는 숨기고 양과 남아 있는 밤 기록은 유지합니다. 고민 없음 또는 고민 원문이 없는 경우 고민·회고를 노출하지 않습니다.
- 조회 실패는 같은 양으로 재시도하고, 403·404는 조회 불가 안내를 표시합니다. 다른 양의 응답이나 화면을 닫은 뒤 도착한 응답은 표시하지 않습니다.
- 상세는 별도 모달로 열립니다. 상단 뒤로가기와 Android 뒤로가기로 닫으면 기존 양떼·스크롤 위치·신규 강조를 유지합니다. 재진입 시 상세는 다시 조회합니다.

메모리 mock만 사용하며 실제 서버·Android HTTP 연동과 소유권 검증은 미완료입니다. 삭제·회고 작성·꾸미기·음악 재생은 제공하지 않고 **카드 쓰기**는 준비 중으로 비활성화합니다. 긴 글·삭제된 카드/고민·고민 없는 밤·기존 회고·조회 실패·없는 양의 예시를 선택할 수 있습니다. 추가 의존성은 없습니다.

### 아침 돌아보기 미리보기

`/dev/morning-reflection`에서 **어젯밤 돌아보기**를 열어 회고 6종을 선택하고 저장할 수 있습니다. 저장된 답변은 같은 밤의 양 상세에 반영됩니다. 조회·저장 재시도, 고민 없음·삭제, 기존 답변, 긴 고민, 저장 불가 시나리오를 제공합니다. 미리보기 안에서만 메모리로 유지되며 나갔다 들어오면 초기화됩니다. 실제 서버·Android HTTP·로그인·영속 저장은 연결되지 않았습니다. 담은 노래·운세·삭제 기능은 포함하지 않습니다.
