# 실제 API 연동 확인

확인일: 2026-11-20 · AWS `https://54.252.207.11/api/v1` · 프론트 #70 이후 후속 확인.

## 확인한 동작

- 임시 계정 가입·동의·생일·낮 안내, 토큰 갱신·로그아웃·재로그인·계정 삭제.
- 글·직접 입력한 노래 카드 접수 `201`, 같은 멱등키 재시도의 동일 카드 ID, 목록의 한 건 유지, 삭제 `204`.
- 내 카드·받은 털실·곡 검색 조회는 이전 `501`에서 `200`으로 바뀌었습니다. 새 계정의 목록과 곡 검색 결과는 비어 있습니다.
- `/stickers`는 `200`과 빈 목록을 반환했습니다. 프론트는 서버 카탈로그의 HTTPS `asset_url`을 사용하고, 로컬 예시 스티커를 추가하지 않습니다.
- 낮의 밤 기록 요청은 `409 NIGHT_CLOSED`로 제한됩니다. 운영 서버의 시간·DB를 변경하지 않았습니다.

테스트 계정과 작성 카드는 검증 후 삭제했습니다. 비밀번호·토큰은 로그와 저장소에 남기지 않습니다.

## 백엔드 보완 요청

| 항목          | 현재 확인                                                                   | 필요한 조치                                                                                                                                    |
| ------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 약관 원문     | API가 제공한 `/terms`, `/privacy`가 `403`                                   | 승인된 본문을 비로그인 HTTPS로 열 수 있게 제공하고 `body_url`과 일치시키기                                                                     |
| 운세          | `503 FORTUNE_UNAVAILABLE`                                                   | 실제 서비스가 읽는 검수된 날짜/별자리 또는 fallback 데이터 준비                                                                                |
| 마무리 재진입 | `NIGHT_CLOSING`에 종료 세션 ID 없음                                         | 해당 종료 세션 ID를 bootstrap에 제공해 `/sessions/{id}/closing-view`와 연결하기                                                                |
| 밤→아침 통합  | `INTEGRATION_backend` `e4d5bfa`에서 BE1 연동 포트가 기본 실패 구현으로 남음 | `FeedPreparationPort`, `ClosingCardPort`, `ClosingCardVisibilityPort`, `MorningCandidatePort`의 실제 BE2 연결 및 동일 밤/세션 저장소 사용 확인 |

마지막 행은 저장소 코드 기준으로 확인한 사항입니다. 운영 JAR의 소스 대응은 별도 확인이 필요합니다. 포트가 미연결이면 밤 세션 생성·마무리·아침 bootstrap에서 `FEED_BUILD_UNAVAILABLE`이 발생할 수 있습니다.

## 남은 운영 검증

밤 시간(한국 21:00~04:00)에 고민 → 세션 생성/재개 → 피드·반응·마무리를 확인하고, 다음 아침(04:00 이후)에 후보·채택·회고·양떼·꾸미기 저장을 같은 임시 계정으로 확인합니다. 빈 카탈로그가 계속되면 이미지·스티커 저장 검증에는 서버 카탈로그와 양 기록이 먼저 필요합니다.
